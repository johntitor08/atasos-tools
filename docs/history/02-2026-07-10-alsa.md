Recurring Environment Gotchas (check these on every new package build)
1. /usr/lib vs /usr/lib64 pkgconfig split: Many autotools packages install .pc files and .so files to /usr/lib/ instead of /usr/lib64/. A symlink exists (/usr/lib/pkgconfig -> /usr/lib64/pkgconfig, created 2026-07-08) so .pc files auto-resolve regardless of which dir a package installs to. .so files still sometimes land in /usr/lib (confirmed again with alsa-lib 2026-07-10 — libasound.so* installed to /usr/lib, not moved this time since it wasn't blocking anything, but keep in mind for future linking issues) and can be manually mv'd to /usr/lib64 + ldconfig for consistency if a future package can't find them.
2. GObject Introspection: packages fail to build when introspection is enabled because Gio-2.0.gir can't be found. Always check for a disable flag before building.
3. SSL certs missing in this environment: use Python urllib with an unverified SSL context for all downloads (see prior sessions for the snippet).
4. Multiple background build processes: always check ps aux | grep <toolname> before launching a new background build.
5. Power loss / hard VM stop can corrupt individual .o files silently: identify and rm the specific stale .o file(s) named in linker errors, then rerun the build — don't assume a full clean rebuild is needed.
6. This environment has no which, pacman, or any package manager — confirmed again 2026-07-10. Use find, direct paths, or ls on known install dirs to check for tool presence instead of which.
7. QEMU sound hardware requires a full guest shutdown + host-side QEMU relaunch with new -audiodev/-device flags — cannot be hot-plugged. If ever changing audio backend/device again, always shutdown -h now in guest first, confirm ps aux | grep qemu-system is empty on host, then relaunch.
