THE WORKING QEMU HOST BOOT COMMAND
Two critical additions vs. the old boot command: blob=true on the GPU device, and memory-backend-memfd with share=on (the share=on was the easy-to-miss piece -- without it, hostmem= on the GPU device is silently ineffective).
qemu-system-x86_64 \
  -drive file=/home/eren/Belgeler/lfs/lfs.qcow2,format=qcow2,if=virtio \
  -m 4096 -smp 4 -enable-kvm \
  -object memory-backend-memfd,id=mem1,size=4096M,share=on \
  -machine pc,memory-backend=mem1 \
  -netdev user,id=net0 -device e1000,netdev=net0 \
  -vga none \
  -device virtio-gpu-gl-pci,blob=true,hostmem=256M \
  -device usb-ehci,id=usb -device usb-kbd -device usb-tablet \
  -display gtk,gl=on \
  -audiodev pa,id=snd0 -device intel-hda -device hda-duplex,audiodev=snd0 \
  -serial stdio
Note: even with this, dmesg | grep drm inside the guest may still show -host_visible in the feature list -- that turned out to be a red herring / not the actual blocker. Do not chase host_visible further; it wasn't the real fix.
THE ACTUAL ROOT CAUSE AND FIX (found by a parallel Claude Code session)
The real bug was not GPU blob/host_visible support. It was that KWin's XWayland dmabuf import was broken in this environment:
kwin_wayland_wrapper: XWAYLAND: [destroyed object]: error 7: importing the supplied dmabufs failed
kwin_wayland_wrapper: (EE) failed to dispatch Wayland events: Protocol error
kwin_wayland_wrapper: kwin_xwl: The X11 connection broke (error 1)
This happened regardless of blob/host_visible/software-rendering settings, because Firefox's window surface was being handed to XWayland either way. The fix is to bypass XWayland entirely and run Firefox as a native Wayland client, which avoids KWin's broken XWayland dmabuf path completely.
WORKING FIREFOX LAUNCH METHOD (must run as eren, NOT root)
Key env vars -- the critical ones that were previously missing/wrong:
* unset DISPLAY (this was the missing piece in earlier attempts -- leaving DISPLAY set caused Firefox to still try the X11/XWayland path even with GDK_BACKEND=wayland set)
* WAYLAND_DISPLAY=wayland-0
* MOZ_ENABLE_WAYLAND=1
* GDK_BACKEND=wayland
Plus profile user.js prefs for extra safety/simplicity:
user_pref("widget.dmabuf.force-disabled", true);
user_pref("gfx.webrender.software", true);
user_pref("layers.gpu-process.enabled", false);
Full working launch pattern (always re-derive XAUTHORITY/session values fresh each boot -- they change every login -- via cat /proc/$(pgrep -u eren plasmashell)/environ | tr '\0' '\n' | grep -E "XAUTHORITY|DISPLAY|DBUS_SESSION_BUS_ADDRESS"):
cat > /tmp/run-firefox.sh << 'EOF'
#!/bin/bash
unset DISPLAY
export WAYLAND_DISPLAY=wayland-0
export MOZ_ENABLE_WAYLAND=1
export GDK_BACKEND=wayland
export DBUS_SESSION_BUS_ADDRESS='unix:path=/run/user/1001/bus'
export MOZ_DISABLE_CONTENT_SANDBOX=1
export LD_LIBRARY_PATH=/root/firefox-152.0.5/obj-build/dist/bin
mkdir -p /tmp/ff-profile
cat > /tmp/ff-profile/user.js << 'PREFEOF'
user_pref("widget.dmabuf.force-disabled", true);
user_pref("gfx.webrender.software", true);
user_pref("layers.gpu-process.enabled", false);
PREFEOF
/root/firefox-152.0.5/obj-build/dist/bin/firefox -no-remote -new-instance -profile /tmp/ff-profile
EOF
chmod +x /tmp/run-firefox.sh
chown -R eren:eren /tmp/run-firefox.sh /tmp/ff-profile
su - eren -c "/tmp/run-firefox.sh"
(As root: cannot run Firefox directly against another user's session -- must use su - eren -c.)

Recurring Environment Gotchas (still applicable, check on every new package build)
1. /usr/lib vs /usr/lib64 pkgconfig/library split: symlink /usr/lib/pkgconfig -> /usr/lib64/pkgconfig exists but .so files still land in /usr/lib sometimes, shadowing newer versions in /usr/lib64 (bit us once with fontconfig -- see Firefox section in prior prompt version if needed). Check ldd + look for duplicates under /usr/lib when a rebuilt library seems to have no effect at runtime.
2. GObject Introspection: pass -Dintrospection=disabled or =false (type varies per-project meson_options.txt) before building any GNOME-stack package.
3. SSL certs missing: use Python urllib with unverified SSL context for downloads.
4. Serial console freezes on long foreground commands -- ALWAYS use nohup cmd > log 2>&1 & echo "PID: $!"; disown then poll with ps aux + tail log.
5. Terminal line-wrapping corrupts heredocs -- keep multi-line script/patch content simple, verify with python3 -c "import ast; ast.parse(open(f).read())" or re-cat after writing.
6. Duplicate command execution -- copy-pasted blocks sometimes run twice; check ps aux for dupes before assuming something's broken.
7. Power loss/kill can corrupt individual .o files silently during kernel builds -- find . -name "*.o" -newer Makefile -exec sh -c 'file "$1" | grep -q ELF || echo BOZUK: "$1"' _ {} \; to find and rm them, then resume the build (incremental, no need for full clean).
8. No package manager -- use find/direct paths.
